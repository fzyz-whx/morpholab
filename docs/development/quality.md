# 最小质量规范

## 当前闸门

启动文档必须准确说明完成状态，仓库内相对链接存在，不含秘密、本机绝对路径或无权发布的影像。`scripts/check_docs.py` 检查 Git 公开文件、本地 Markdown 链接与部分凭据模式；它不是完整秘密扫描或许可审计。提交前运行差异空白检查。

最小 GitHub Actions 在 Windows / Ubuntu 运行锁定安装、ruff lint/format、pytest、重点 mypy 和公开文档检查。远端任务结果在 push 后单独核对，配置存在不代表 CI 通过。

## 随实际模块加入的检查

- Python：锁定依赖、ruff lint/format、pytest，以及数据与核心计算的 mypy。CI 使用极小合成 fixture，不下载真实大数据或执行长训练。
- 数据：时间顺序、缺帧/重复帧、尺寸与标注对齐、文件 hash、官方实验组划分、路径安全。
- 模型：shape、有限数值、seed、梯度、CPU、小型训练/保存加载/恢复；正式实验记录数据与模型版本。
- 前端：TypeScript strict、lint、组件测试、构建；核心真实交互以 Playwright E2E 验收，并审视两种桌面尺寸截图。
- 后端：输入边界、路径约束、错误状态、作业持久化与恢复、预测链集成。
- 发布：干净克隆复现、所有适用 CI 检查、命令及图片链接、逐项第三方许可和真实结果。

不为可逆文案小改增加镜像实现的测试。新增程序行为必须有能发现实质错误的测试。检查失败先修复；报告执行命令与实际结果，不能只因存在 tests 文件就称通过。
